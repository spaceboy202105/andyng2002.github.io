# 中英文个人学术主页开发规范

日期：2026-10-08。

状态：功能范围、测试范围和第二轮原型 A 已由用户确认；本规范用于后续正式开发。网站实现、正式 CV 和线上发布尚未完成。规范和七项任务已发布到 GitHub Issues，编号见 `docs/implementation-issues.json`。

## Problem Statement

用户希望从零建立个人主页，让学术同行、导师和潜在合作者迅速了解其研究方向、学术成果与个人项目，并能阅读 Blog、取得联系方式及下载中英文 CV。

旧网站已从当前工作树清理。现有资料是设计说明、术语表和本地素材，还没有可运行的网站或测试入口。开发需要把已确认的设计转成一致的内容规则、页面行为和验收要求，避免自动挑选项目、公开私人资料，或把已有简历参考稿误当成正式 CV。

## Solution

建立以作品展示为主的中英文网站。首页展示简介、照片、代表论文、代表项目、最新文章和联系入口；学术成果、个人项目与 Blog 各有完整列表，文章有独立阅读页。

网站采用暖白背景、深灰文字和蓝色强调色，以排版、作品图片和少量动画体现个人风格。简介、学术成果说明及项目说明提供完整中英文，Blog 允许单语发布。内容通过 Markdown 维护，正式 CV 重新制作成两份具有 LaTeX 学术简历风格的 PDF。

开发以构建后的网站为主要验收对象，并检查实际公开文件。本文描述需要交付的行为，不把某个框架、依赖版本或尚不存在的命令当成已确定事实。

## User Stories

1. 作为首次访问的学术同行，我希望在首页直接看到姓名、研究方向和代表作品，以便迅速判断研究关联。
2. 作为访客，我希望看到用户指定的最新照片，以便形成清晰的个人印象。
3. 作为学术同行，我希望从首页代表论文进入完整成果列表，以便继续了解研究工作。
4. 作为论文读者，我希望看到正式题名、作者顺序、发表信息和年份，以便准确识别成果。
5. 作为论文读者，我希望区分预印本、在投和正式发表状态，以免误解成果进展。
6. 作为论文读者，我希望打开有效的论文与代码链接，以便阅读和复现相关工作。
7. 作为中文或英文读者，我希望以熟悉的语言阅读研究贡献说明，以便理解论文解决的问题。
8. 作为潜在合作者，我希望看到项目截图、用途和个人职责，以便了解用户实际完成的工作。
9. 作为项目访客，我希望打开项目的代码或演示入口，以便进一步查看成果。
10. 作为项目访客，我希望能阅读相关 Blog，以便了解设计过程和实验结论。
11. 作为网站所有者，我希望自己决定展示哪些项目和代表作品，以免候选素材被自动发布。
12. 作为访客，我希望完整列表与首页精选有所区分，以便先浏览重点，再查阅更多内容。
13. 作为 Blog 读者，我希望从首页看到最新文章并进入完整列表，以便发现持续更新的内容。
14. 作为 Blog 读者，我希望每篇文章有独立阅读页，以便阅读和分享。
15. 作为研究文章读者，我希望公式正确显示，以便理解推导。
16. 作为技术文章读者，我希望代码清晰显示并有语法高亮，以便阅读示例。
17. 作为文章读者，我希望图片、图注和正文保持对应，以便理解图示证据。
18. 作为长文读者，我希望通过章节目录定位内容，以便快速跳转。
19. 作为文章读者，我希望看到发布日期、更新日期和主题标签，以便判断内容时效与主题。
20. 作为文章读者，我希望打开关联的论文和项目，以便继续追查来源。
21. 作为首次从站点默认入口访问的读者，我希望先看到英文界面，以便国际访客直接阅读。
22. 作为偏好中文的读者，我希望切换后记住语言选择，以免每次访问都重新选择。
23. 作为当前页面的读者，我希望切换语言后仍在对应内容上，以免丢失阅读位置。
24. 作为 Blog 读者，我希望单语文章在两种界面都能找到，以免因界面语言不同而漏掉文章。
25. 作为 Blog 读者，我希望知道正文的原始语言，并在有译文时切换到对应版本，以便选择阅读语言。
26. 作为学术读者，我希望双语页面保留正式论文题名和作者信息，以便查找准确的公开记录。
27. 作为潜在合作者，我希望在简介附近和页脚找到有明确含义的联系图标，以便选择联系方式。
28. 作为 CV 阅读者，我希望同时看到中文与英文入口，以便主动选择版本。
29. 作为 CV 阅读者，我希望打开重新排版、结构对应的学术 CV，以便清晰查阅经历和成果。
30. 作为网站所有者，我希望公开 CV 只包含已核对的公开内容，以免暴露私人信息或未公开工作。
31. 作为手机访客，我希望所有页面适应屏幕宽度，以便连续阅读而不左右拖动整页。
32. 作为键盘使用者，我希望能够操作导航、语言切换和链接，并看清焦点，以便独立浏览。
33. 作为偏好减少动态效果的访客，我希望装饰动画停止，以便舒适阅读。
34. 作为访客，我希望缺少代码、演示或 CV 文件时不出现无效入口，以免点击失败。
35. 作为访客，我希望不存在的地址能提供返回首页的入口，以便继续浏览。
36. 作为网站所有者，我希望编辑 Markdown 后能更新相应页面，以便日常维护内容。
37. 作为内容维护者，我希望同一条目可以供首页和列表复用，以免两处内容不一致。
38. 作为内容维护者，我希望缺失必填信息或无效引用能够得到清楚的构建错误，以便准确修复。
39. 作为网站所有者，我希望本地原始素材不进入公开仓库或发布文件，以便只公开经过选择的内容。
40. 作为网站所有者，我希望检查失败时保留原有线上版本，以免发布不完整的网站。
41. 作为后续开发者，我希望用访客能观察到的行为验证改动，以便在调整内部结构后继续信任测试。
42. 作为网站所有者，我希望交付说明包含实际验证结果和仍缺少的素材，以便判断是否可以上线。

## Implementation Decisions

### 已确认的产品约束

- 首页顺序为简介、代表论文、代表项目、最新文章和联系方式。
- 学术成果以论文为主。个人项目使用卡片与外部链接，长篇说明关联 Blog，初版不设独立项目详情页。
- 项目和代表作品由用户选择。已存在的素材、简历中的条目和测试样例都不能自动获得展示资格。
- 采用浅色视觉：暖白背景、深灰文字、蓝色强调色。论文使用左图右文列表，项目使用较大的图片卡片。
- Blog 支持公式、代码高亮、图片及图注、长文目录、日期、标签、关联内容和可选译文。
- 联系入口包含 Email、Google Scholar、GitHub、ORCID、中文 CV 和 English CV。图标链接放在简介下方，页脚保留同样的入口。

### 首版公开内容（2026-10-08 用户确认）

用户选择先上线已确认的简介、照片和联系信息，暂不展示未选作品；中英文 CV 只收录已确认的公开信息。论文、项目和 Blog 的功能仍完整实现，并通过隔离的合成内容验收。正式首页省略空内容区，完整列表可以显示简短空状态。正式 CV 此轮使用姓名、联系方式、已核对教育经历和研究兴趣；不加入尚未选择的论文、项目、荣誉或有疑点的导师信息。页数由获准内容决定，不为达到两页补写经历。

2026-10-09 核对发现旧 Google Scholar 链接指向他人，用户明确选择省略 Google Scholar。首版网站和两份 CV 均不提供该入口；不猜测替换链接。其余联系入口按原批准范围保留。

### 技术组织与职责

使用 Markdown 驱动、以静态网页及文件为输出的组织方式。运行时交互集中在语言选择和必要导航。初版不需要账号、数据库或内容编辑后台。具体生成工具、编程语言和测试框架在实施计划中选定，本规范要求的外部行为不随工具改变。

| 职责 | 输入 | 操作 | 输出 |
| --- | --- | --- | --- |
| 公开内容读取与校验 | 已选定的条目、正文及公开资源 | 校验字段、语言、引用和公开资格 | 页面可直接使用的公开内容 |
| 页面生成 | 公开内容与界面文案 | 生成首页、列表及文章页 | 中英文网页与导航 |
| 语言选择 | 当前页面语言、用户点击和本地偏好 | 确定目标页面及可用正文版本 | 保持内容对应关系的切换结果 |
| 共享页面部件 | 当前语言与条目数据 | 渲染导航、联系入口、论文列表及项目卡片 | 一致的页面呈现 |
| CV 制作 | 已核对经历、公开论文和用户选定项目 | 重新排版、检查中英文对应和分页 | 两份最终 PDF |
| 构建与发布检查 | 网站构建结果和最终公开文件 | 检查行为、链接与公开范围 | 可发布文件及检查结果 |

这些是职责划分，不要求为每行建立独立包、服务或通用框架。能用一个清楚的函数或组件完成的职责不再拆层。

### 内容记录与关联

- 每个条目有稳定标识，用来关联首页精选、完整列表、文章和译文。修改显示标题不应意外创建新条目。
- 公开资格与首页精选是两个独立概念。只有已批准公开的条目才可进入列表，只有用户指定的代表作品才可进入首页精选。
- 简介、论文说明和项目说明必须具有中英文版本。正式题名、作者顺序、机构名称及发表信息保留准确的原始记录。
- 论文条目的正式题名、作者、时间、准确状态及中英文贡献说明为必填信息，缺失时保留为本地素材。论文链接、代码链接和成果图按实际资料提供，缺少时隐藏相应入口或图片区域，不生成虚假链接或图片。
- 项目条目包含名称、用途、个人职责、中英文说明、截图及实际可用的外部链接。用户未选择的项目不进入公开内容输入。
- Blog 文章包含稳定标识、正文语言、标题、发布日期、正文和主题标签，可具有摘要、更新日期、译文及关联内容。更新日期不能早于发布日期。
- 译文引用同一篇文章的稳定标识，不能仅凭相似标题推断两篇文章互为译文。每个文章组明确记录原文语言；同组版本声明保持一致，原文版本必须存在。
- 同一研究的论文和项目可以相互关联，分别介绍研究贡献和实际功能，不复制成长篇重复介绍。
- 内容校验发生在读取公开内容时；页面只接收校验通过的数据，不在每个组件内重复猜测字段形状。

### 双语与导航

- 从没有显式语言的入口访问时，优先使用用户已保存的语言选择，否则默认英文。
- 明确指定语言的页面链接保持该语言；保存的偏好不覆盖别人分享的指定语言链接。
- 用户手动切换后，在浏览器本地保存偏好。浏览器不允许保存时，本次切换仍可使用，后续访问按入口规则处理。
- 首页、列表和文章在切换后保持内容对应关系，不统一跳回首页。
- 两种界面展示相同的已公开 Blog 集合。没有译文时保留原文，明确标注正文语言，不能展示空白正文或自动伪造译文。
- 有译文时打开同一文章的对应版本。界面语言与正文语言分别处理。
- 中文和英文 CV 的入口同时存在，不因为界面语言而隐藏另一份。

### CV 与公开资料

- 正式 CV 重新制作，采用 LaTeX 学术简历式的白底、单栏和清楚的章节排版。保留可编辑源稿与可复现的生成说明。
- 中英文结构与事实对应，各以两页为目标，内容增加时自然延长，不靠过小字体强行压缩。
- 内容包括教育经历、研究兴趣、论文、用户选定项目、奖项和技能。首版学术成果仅收录已有公开链接的条目。
- 预印本不写成已录用或已发表，未公开的在投工作暂不收录。存在疑点的经历与日期先核对，不自行推断修正。
- 已有简历及其删除私人字段后的副本仅作资料参考，不得替代正式 CV。
- 原始素材保持本地保存，并通过 Git 忽略规则排除。构建只读取明确批准的公开输入，不能递归复制原始素材目录。
- 公开照片使用用户指定的最新照片生成适合网页的文件，保留正确比例，清除拍摄元数据。原始大图不直接作为每次页面访问的默认下载资源。
- 公开页面、文件与待提交内容不包含手机号、年龄、性别、住址、证件信息、第三方未公开投稿动态或未经批准的成果。

### 页面与编码规范

- 优先使用平台语义元素实现链接、按钮、标题和导航，使键盘操作与屏幕阅读软件能识别其含义。
- 联系图标具有可识别名称和文字提示。焦点必须可见，状态不能只靠颜色区分。
- 桌面端简介与照片并排，手机端转为单列。图片、标题和正文不造成整页横向溢出；宽代码和公式仅在自身区域内滚动。
- 装饰动画限于轻微淡入和悬停反馈，遵守访客减少动态效果的设置。内容可见性不依赖动画是否成功执行。
- 复用相同的页面布局、语言文案和条目部件；不为中英文复制两套页面业务逻辑。
- 颜色、字号和间距使用少量集中定义的样式值；避免同一视觉规则散落在各页。
- 新依赖必须解决具体需要。先使用已有工具和平台能力，不为简单格式转换或几行逻辑增加依赖。
- 技术栈确定后，用其标准工具统一格式、静态检查和构建，并保留依赖锁定文件，使干净环境可以复现。清理旧模板留下的冲突规则，不继续沿用失效配置。
- 对外部链接检查允许的协议，对日期和引用检查格式及有效性。错误信息指出具体条目、字段和修复方向，不以空字符串或默认假值掩盖错误。
- 文本与数据按所选模板工具的安全方式输出，不通过拼接不受约束的 HTML 生成正文或链接。Markdown 正文同样经过 HTML 标签、属性和地址协议的过滤；公式禁用可信扩展，目录与本地链接按实际输出和部署前缀生成。富文本扩展只在有真实内容需要时引入。
- 注释只解释代码本身不能说明的原因。只有真实重复或复杂度需要时才抽取共享逻辑，不预建插件层或后端接口。

### 缺失内容、构建与发布

- 缺少代码、演示或其他可选链接时，不显示相应按钮。
- 正式 CV 文件缺失时，不提供下载入口。该状态可以用于预览，但在本次完整网站交付中仍记为未完成。
- 尚未选定内容时，预览可使用明确标注的布局占位；公开首页不显示空精选区、虚构条目或未标明的示例内容。
- 不存在的页面提供清楚的说明以及返回首页和主要栏目的入口。
- 内容校验或构建失败时停止发布，保留已经在线的版本，并输出可定位的错误。
- 自动发布只上传通过检查的网站产物。建立发布流程时再核对目标站点和仓库权限，不从旧模板地址推断新站地址。
- 实施计划必须提供一个可复现的完整检查入口，串联内容校验、构建、主要行为检查和公开文件检查。入口采用所选工具的常规方式，不另建通用任务系统。

## Testing Decisions

### 已确认的测试范围

用户已确认以浏览器检查构建后的网站为主，同时检查构建产物中的 CV、链接和公开内容范围。仅对浏览器难以覆盖的内容校验补充小测试。

主要测试入口是接近发布状态的本地网站：使用实际构建结果，像访客一样打开页面和操作链接。不以内部组件名称、函数调用次数、样式类名称或源码快照代替行为验证。

公开文件检查是必要补充。页面没有链接到某份资料，并不能证明那份资料没有被复制到网站输出；因此必须直接检查输出文件清单和最终文件内容。

### 构建产物与人工检查

- 检查待提交文件及网站输出，只含批准的公开内容，不含本地原始素材、简历参考副本或未公开研究。
- 检查实际 CV 文件的语言、来源身份、文字、链接及逐页渲染，确认不是参考稿改名。中英文事实对应，没有裁切、溢出或错误论文状态。
- 检查公开照片的画面与元数据，并核对移动端实际加载资源，避免直接加载原始大图。
- 检查内部链接和文件目标确实存在。外部链接在上线前核对；遭遇网络限制或服务拒绝时记录实际状态，不能直接报为有效。
- 用不含真实私人资料的测试样例验证排除规则，避免测试日志泄露需要保护的数据。
- 在自动发布流程建立后，执行一次从受控内容更新到站点更新的完整检查。初次对线上部署的操作仍须符合当时用户授予的范围。

当前工作树没有可复用的应用测试、运行命令或构建配置，旧站历史不是现成测试入口。此前的检查只证明了素材处理、文档一致性及 Git 忽略规则，不代表网站验收已经通过。
