## 已确认的决定

- 主要访客是学术同行和导师，次要访客是潜在合作者和招聘方。
- 首页让访客迅速了解研究方向和代表作品。
- 内容包括个人简介、学术成果、个人项目和 Blog。
- 视觉呈现以作品列表、排版和作品图片为主，不需要三维交互。
- 简介、学术成果和个人项目提供完整的中英文内容。
- Blog 以研究解读和项目记录为主，文章可以只提供一种语言，有译文时再提供切换。

## 页面结构

- 首页按顺序展示简短介绍、代表论文、代表项目、最新文章和联系方式。
- 学术成果、个人项目和 Blog 各有完整列表页。
- Blog 文章有独立阅读页。
- 学术成果以论文为主，展示题目、作者、会议或期刊、年份、成果图，以及论文和代码链接。
- 个人项目展示工具、系统和开源作品，说明解决的问题、个人职责，并提供截图和链接。
- 同一个研究可以关联论文和项目。论文条目介绍研究贡献，项目条目介绍实际功能。
- 个人项目初版采用项目卡片和外部链接，长篇说明可关联 Blog，不要求独立的项目详情页。
- 具体展示哪些项目由用户决定。素材中的项目列表不自动成为网站展示列表。

## 语言

- 首次访问默认英文，手动切换后记住选择。
- 简介、成果和项目提供完整中英文内容。
- Blog 的两种界面展示同一套文章。没有译文的文章保留原文，并标注文章语言。
- 切换界面语言不会隐藏单语文章。
- 切换语言时尽量保留当前页面或文章；没有对应译文时，保留原文并明确标注语言。
- 论文正式题名、作者姓名和发表信息保留原始记录，解释性简介提供中英文。

## Blog 阅读

- 支持数学公式、代码高亮、图片和图注。
- 长文章提供章节目录，并显示发布日期、更新日期和主题标签。
- 文章可以关联论文、个人项目和已有译文。
- 初版不加入评论区、全文搜索或邮件订阅。

## 内容维护

- 使用 Markdown 文本文件维护内容。
- 新增论文时填写作者、年份和链接等条目信息。
- 新增 Blog 时添加文章及配图。
- 目标流程是提交到仓库后自动发布。具体构建工具和部署配置尚未选择或实施。

内容处理过程如下：

1. 从本地 `raw/` 中选择用户确认可以公开的资料，补齐论文状态、条目信息和链接。
2. 将网站内容写成 Markdown，将正式 CV 制作为重新排版的中英文 PDF。

4. 检查内容、页面显示和链接后发布生成的网站。源素材目录不进入公开仓库或网站产物。

本阶段只确定上述流程，不安装构建工具或配置线上发布。

## 内容缺失时的处理

- 未指定代表作品时，设计预览可以显示明确标注的布局占位。上线页面不使用虚构论文、项目、图片或链接。
- 某项内容没有代码、演示或其他链接时，不显示对应按钮。
- 中英文 CV 的最终文件尚未制作时，不用原始简历或参考副本替代，也不提供无效下载链接。
- 某个栏目尚未准备内容时，预览明确标注，正式首页不显示空的精选区。
- 404 页面提供返回首页和主要栏目的入口。

## 验收标准

以下是后续实现必须达到的条件，当前尚未执行网站验收：

- 首页和完整列表分别展示精选与全部已批准内容，项目没有未经用户选择的条目。
- 中文和英文导航、简介、成果说明和项目说明完整；语言切换保留页面语境，并记住手动选择。
- 单语 Blog 在两种界面中都能找到，文章原文语言及译文入口显示正确。
- 公式、代码、图片、图注和文章目录在桌面与手机尺寸下都可阅读。
- 联系入口指向正确地址，中英文 CV 分别打开对应的重新排版版本。
- 公开文件中没有私人字段、未公开的在投工作、资料参考副本或整个 `raw/` 目录。
- 页面没有横向整体溢出；键盘可以操作导航、语言切换和链接；减少动态效果的偏好生效。
- 内部链接、文件下载、关联文章和图片可用，缺少链接的条目没有空按钮。
- 编辑一篇 Markdown 后，能生成对应页面；新增条目能出现在正确的列表中。
- 以实际构建结果、页面检查和链接检查证明完成，不能仅凭源文件存在作出完成判断。
